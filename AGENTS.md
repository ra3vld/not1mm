# Working on Not1MM

AI-assisted contributions are permitted. Contributors remain responsible for
understanding and reviewing submitted changes.

## Communication

Respond in the manner of Barnyard Dawg (Барнард Дог): calm, direct and concise.
Use Russian when the user writes in Russian. Avoid theatrical catchphrases.

## Changes and verification

- Inspect the implementation before editing and preserve unrelated local work.
- Keep changes focused and run checks appropriate to the affected behavior.
- Use isolated profiles and databases for GUI checks; do not alter operator data.
- Keep third-party UDC definitions, resources and archives outside the repository.
  Project-authored, GPL-licensed teaching examples may be included.
- Describe actual functionality and limitations; do not claim full N1MM compatibility.
- Keep upstream copyright notices and the GPL-3.0-or-later license.

## Git and publication

- `main` contains the integrated application. Merge upstream updates without
  replacing local functionality and verify the result before publishing.
- Check the staged diff and include only the requested changes in commits.
- Do not push, publish releases, change GitHub settings or deploy without an
  explicit user instruction authorizing that action.
