# Пользовательские соревнования

[Пошаговое подключение UDC + SEC + HLP со скриншотами](udc-setup-ru.md).

Откройте **File → Import User Contest…**, выберите оригинальный `.udc` и нажмите
**Validate and preview**. Недостающие `.sec` / `.txt` добавьте кнопкой
**Add dependency files**. Если соревнованию нужен свой справочник CTY.DAT,
выберите его в диалоге. После проверки нажмите **Import**.

Соревнование появится в **New Contest** с пометкой `[UDC]`. При создании журнала
задайте дату, категорию и свой обмен. Данные станции берутся из настроек и
сохраняются для этого журнала. Новые определения добавляются без Python-плагинов
и пересборки приложения.

Обновление UDC действует на новые журналы. Существующие сохраняют исходные правила,
справочники и версию движка. **Export User Contest Definition…** возвращает
оригинальное определение и сопутствующие файлы из снимка журнала.

Перед первой миграцией базы создаётся файл `*.pre-udc-*.bak`. Старые связи не
пересчитываются. Журналы независимы, включая связи с одинаковым временем и позывным.

Поддерживается часть формата UDC. Неподдерживаемое активное правило блокирует
импорт с диагностикой. UDC не исполняет SQL, Python или команды оболочки.
[Таблица совместимости и архитектура](user-defined-contests.md).
Перед соревнованием проверьте, что определение отражает его действующие правила.

## Подсказки и автоподстановка

В **File → Configuration Settings → Options** включите **Use Call History**.
Через **File → Load Call History File** выберите файл в формате N1MM: строка
`!!Order!!` содержит названия полей, дальше идут данные через запятую.
Расширение `.hlp` или `.txt` не влияет на импорт. В строке состояния появится число
загруженных записей; ошибочный файл сохраняет прежнюю базу подсказок.
Импорт действует на текущую базу журнала.

При вводе позывного показывается подсказка. После **Tab**, **пробела** или щелчка
по полю обмена заполняются подходящие пустые поля согласно определению UDC.
Распознанный район или секция имеет приоритет перед географическим локатором.
Неполные значения остаются подсказками. **Принятый порядковый номер вводится
оператором.**

Уже введённые значения сохраняются. При исправлении позывного прежняя
автоподстановка убирается, если оператор её не редактировал. Позывные с `/P`,
`/M` и другими суффиксами ищутся отдельно. Для существующего журнала не требуется
повторно импортировать UDC или менять версию движка.

## Время работы и переходы между диапазонами

**File → UDC operating / OFF times** считает полные UTC-минуты работы и перерывов.
Если календарные границы отсутствуют или совпадают, задайте фактические даты
начала и конца. Отчёт OFF не меняет очки QSO.

Поддерживаются интервальные повторы, счётчики переходов между диапазонами/модами
и таймеры удержания диапазона. Счётчик и оставшееся время отображаются в строке
состояния. Превышение лимита и ранний переход дают предупреждения; связи
сохраняются без штрафных очков. Состояние восстанавливается из журнала после
исправления, удаления и перезапуска. Ручного управления подтурами командой TOUR нет.

[INTERVAL.udc](../examples/udc/INTERVAL.udc) — учебный пример интервальных повторов
и ограничений переходов, а не правила официального соревнования.

## FT8 / FT4

FT8 и FT4 принимаются в UDC с `Mode=BOTH`. Для знакомства импортируйте
[FTMIX.udc](../examples/udc/FTMIX.udc), создайте новый журнал и укажите собственный
локатор в обмене. В WSJT-X включите отправку Logged ADIF по UDP. Приёмник Not1MM
слушает порт 2237 и группу `224.0.0.1`; при работе в песочнице нужен сетевой доступ.

Приём использует время, частоту, локатор и знаковые рапорты из сообщения и сохраняет
набранные вручную поля текущей связи. Повторная доставка сообщения не создаёт вторую
запись. Более поздняя самостоятельная QSO сохраняется и проверяется по правилам
соревнования. Недостающие обязательные поля вызывают ошибку и не угадываются.

FT4 экспортируется в ADIF как `MODE=MFSK`, `SUBMODE=FT4`, FT8 — как `MODE=FT8`.
В Cabrillo обе моды обозначаются DG. Управление декодером и передачей WSJT-X
не входит в эту поддержку. Оба примера UDC учебные.

Для новых возможностей импортируйте UDC и создайте новый журнал. Существующие
журналы сохраняют прежние правила и автоматически не преобразуются.

## Тестовый корпус

Сторонние тестовые UDC, справочники и архивы хранятся вне репозитория:
по умолчанию в `../not1mm-external-data/udc`. Другой каталог задаётся через
`NOT1MM_UDC_CORPUS`. В Git остаются сведения об источниках и SHA-256.
[Инструкция к тестовому корпусу](../test/fixtures/udc/README.md) описывает подготовку;
[запуск тестов](user-defined-contests.md#testing-and-packaging) — в общей документации.
